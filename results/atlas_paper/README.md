# Atlas paper result exports

Two CSVs for loading into Pweave/pandas for the paper's tables/figures.

## `atlas_full_results.csv` — tidy/long format, one row per (domain, dataset, model, config, metric)

Columns: `domain, dataset, n_eval, eval_unit, model, config, metric, value, source_doc`.

- `config` ∈ {`normal`, `identity_free`} — the LEACE patient/subject-identity erasure axis.
- `metric` names are domain-specific (see each domain's `docs/*_results.md` for full methodology):
  epilepsy = `sens_at_{1,10}_FPday`, `AUC_FA_0p1_10`, `F1`; sleep = `balanced_accuracy`,
  `cohens_kappa`; brain_age = `R2`; bci/cogneuro = `norm_BA`/`LOSO_BA`; brain_to_image = `top1_retrieval`.
- Pivot example for a normal-vs-identity-free delta table:
  ```python
  import pandas as pd
  df = pd.read_csv("atlas_full_results.csv")
  epi = df[df.domain == "epilepsy"]
  epi.pivot_table(index=["dataset","model"], columns="config", values="value")
  ```
- **Caveat**: `n_eval` is the recordings/subjects in the eval split, not epochs/windows —
  see the source doc for full split sizes (train/dev/eval) and epoch counts.

## `moabb_leaderboard_summary.csv` — MOABB identity-free leaderboard, paradigm-level aggregate

One row per (paradigm, method, scoring, verdict) with the count/rate of datasets landing
in that verdict bucket, plus mean pooled/per-trial Δ across all `ok` datasets in that
paradigm×method×scoring cell.

**Important — TCM and REVE use DIFFERENT native verdict vocabularies, not directly
comparable as a single "trap rate":**
- **TCM (classical control)** verdict ∈ {`task-carried`, `no-transfer`} — a **per-trial-only**
  classification (does per-trial skill clear the 0.55 gate after erasure or not). TCM's script
  does not use the word "TRAP" at all.
- **REVE** verdict ∈ {`TRAP`, `task-carried`, `no-transfer`} — computed separately for the
  **pooled** and **per-trial** scoring passes (two different rows/files per dataset).

Do not join these into one column without preserving `method` and `scoring` — an earlier
draft of this table conflated them and mis-attributed a "0% pooled TRAP" figure to TCM
that was actually just TCM's own verdict field never using that label. Recomputed directly
from the on-disk per-dataset CSVs (not hand-typed) to catch exactly this kind of error.

**Headline (from this table):** REVE pooled TRAP rate is high (MI 100%, ERP 64%, SSVEP 50%)
and collapses to near-zero under per-trial scoring (MI 0%, ERP 0%, SSVEP 17%) — the pooled
"identity trap" is largely a pooling-metric artifact, not a per-trial decoding failure. This
is a *separate, complementary* finding to the Atlas epilepsy/sleep results (which score
continuous/event-level clinical detection, not single-trial pooled decode).

## Per-dataset detail (appendix tables)

The full per-dataset rows behind the summary above are the existing CSVs in
`emeg-fm/results/moabb_fmscope/`: `tcm_pertrial{,_erp,_ssvep}.csv` (classical control),
`leaderboard_{leftright,erp,ssvep}{,_pertrial}.csv` (REVE). 59 distinct MOABB datasets
total across all of these (see `docs/atlas_vs_neuroatlas_coverage.md`).
